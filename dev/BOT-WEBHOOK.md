# Включение вебхука игрового бота

Нужно для двух вещей сразу: чтобы работала **классическая реферальная ссылка**
`t.me/<бот>?start=ref_<id>` (та, что открывает чат бота), и чтобы бот **мог
писать игрокам в личку** — без чего гейт разрешения на входе в приложение
бессмысленен.

Ссылка `?startapp=ref_<id>`, которая открывает сразу Mini App, работает **уже
сейчас** и вебхука не требует. Здесь — только про вторую половину.

## Почему вебхук, а не опрос

Telegram допускает на один токен **либо** `getUpdates`, **либо** webhook. Опрос
`getUpdates` в этом проекте занят операторским ботом (`server/workers.js`) — он
держит кнопки выводов и `/admin`. Второй опрашивающий отобрал бы их у живого
сервера, и никакой ошибки при этом не возникло бы: поллер просто перестал бы
получать апдейты.

У игрового бота сейчас **нет ни того, ни другого**, поэтому вебхук на нём
ничего ни у кого не забирает.

| | |
|---|---|
| игровой бот | `8707351993`, `@Libbbtestbot` (`TG_BOT_TOKEN`) |
| операторский | `8642947082` (`TG_OPS_BOT_TOKEN`) |
| маршрут | `POST /tg-webhook` на том же сервере, что и игра |
| код | `server/routes/tg-webhook.js`, отправка — `server/tg-game.js` |

Токены проверены — **это разные боты**. Если когда-нибудь окажутся одинаковыми,
сервер скажет об этом при старте и напишет в топик алертов: включённый вебхук
в этом случае отберёт опрос у операторского бота.

## 1. Две переменные окружения

Их сейчас нет, и без них маршрут отвечает `503` и пишет в алерты — намеренно, а
не молча.

```bash
ssh -i ~/.ssh/liberty_do root@178.128.136.68
```

Секрет генерируется **на сервере** и никуда не копируется — ни в чат, ни в
заметки. Он нужен только двум сторонам: этому файлу окружения и самому Telegram.

```bash
printf 'TG_WEBHOOK_SECRET=%s\n' "$(openssl rand -hex 32)" >> /srv/liberty/env
printf 'GAME_URL=%s\n' 'https://libertymmorpg.online' >> /srv/liberty/env
systemctl restart liberty-next
```

Проверить, что подхватилось (значение не печатаем):

```bash
grep -c '^TG_WEBHOOK_SECRET=' /srv/liberty/env
curl -s localhost:3000/health
```

## 2. Сказать Telegram, куда слать

Одной командой, там же на сервере — так секрет и токен не проходят через
локальную машину:

```bash
set -a; . /srv/liberty/env; set +a
curl -s "https://api.telegram.org/bot${TG_BOT_TOKEN}/setWebhook" \
  -d "url=${GAME_URL}/tg-webhook" \
  -d "secret_token=${TG_WEBHOOK_SECRET}" \
  -d 'allowed_updates=["message"]' \
  -d 'drop_pending_updates=true'
```

`allowed_updates=["message"]` — бот читает только сообщения; ничего другого
маршрут не обрабатывает, и просить лишнее незачем.

`drop_pending_updates=true` — у бота могли скопиться непрочитанные `/start` за
всё время, пока их никто не читал. Разбирать их задним числом смысла нет:
человек, написавший `/start` месяц назад, не ждёт ответа сейчас.

Ожидаемый ответ:

```json
{"ok":true,"result":true,"description":"Webhook was set"}
```

## 3. Проверить

```bash
set -a; . /srv/liberty/env; set +a
curl -s "https://api.telegram.org/bot${TG_BOT_TOKEN}/getWebhookInfo"
```

Смотреть на три поля:

| поле | что должно быть |
|---|---|
| `url` | `https://libertymmorpg.online/tg-webhook` |
| `pending_update_count` | `0`, или падает при следующем запросе |
| `last_error_message` | **отсутствует** |

Если там `Wrong response from the webhook: 503` — переменная не задана или
сервер не перезапущен. Если `403` — не совпадает секрет.

Живая проверка: открыть чат бота с **другого** аккаунта и отправить

```
/start ref_1199957588
```

Бот должен ответить приветствием с кнопкой, а в `player_logs` появиться строка
`referralRegistered` (или `refuse:referralRegistered` с причиной — например,
если этот аккаунт уже был кем-то приглашён):

```bash
set -a; . /srv/liberty/env; set +a; cd /srv/liberty/next
node -e "const{query,close}=require('./server/db');(async()=>{
  const{rows}=await query(null,\"SELECT event, meta, created_at FROM player_logs
    WHERE event LIKE '%eferral%' ORDER BY created_at DESC LIMIT 5\");
  rows.forEach(r=>console.log(r.created_at.toISOString(), r.event, JSON.stringify(r.meta)));
  await close();})()"
```

## Как выключить

```bash
set -a; . /srv/liberty/env; set +a
curl -s "https://api.telegram.org/bot${TG_BOT_TOKEN}/deleteWebhook"
```

**Обязательно** сделать это перед тем, как включать `getUpdates` на игровом боте
по любой причине — иначе опрос будет молча возвращать пустоту. Это единственный
способ, которым две половины могут подраться, и он не даёт никакой ошибки.

## Что происходит с `/start ref_` от человека без аккаунта

Обычный случай: ссылку прислали тому, кто в игру ещё не заходил. Аккаунта нет,
привязывать реферала не к чему.

Приглашение **не выбрасывается**: оно запоминается за telegram id и применяется
при первом входе в приложение (`takePendingRef`, `server/app.js`). Срок жизни —
`TG_PENDING_REF_TTL_MS`, по умолчанию **7 суток**.

Ограничение, которое стоит знать: этот список живёт **в памяти процесса**.
Перезапуск сервера — а деплой это перезапуск — стирает всё, что в нём накопилось.
На практике окно почти всегда секунды (человек жмёт `/start`, видит кнопку и тут
же открывает игру), так что семь суток — это потолок, а не обещание. Если
понадобится, чтобы приглашение переживало деплой, его надо класть в таблицу `kv`;
сейчас этого не делается сознательно, чтобы не писать в базу на каждый `/start`
от случайного человека.

Повторный `/start` по той же ссылке ничего не удваивает: `update_id`, уже
обработанный, отбрасывается, а сама регистрация — один условный `UPDATE`,
который отказывает второму пригласителю (`registerReferral`,
`server/db/repos/players.js`).

## Что видно, если кто-то нашёл адрес

Маршрут публичный по своей природе. Обращение без правильного заголовка
`X-Telegram-Bot-Api-Secret-Token` отклоняется и **считается**: в `/health`, в
ключе `tgWebhook`, счётчик называется `badSecret`. Там же видно `configured`
(задан ли секрет вообще), `pending` (сколько приглашений ждёт первого входа),
`received`, `failed`, `applied`, `expired`, `unconfigured`.

Ненулевой `badSecret` означает ровно одно: адрес кому-то известен. Сам по себе
это не взлом — секрет по-прежнему стоит между этим кем-то и поддельным
рефералом, — но это повод сменить секрет, повторив шаги 1 и 2.
